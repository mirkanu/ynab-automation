## Copywriting Contract

### Primary CTAs
| Button | Copy | State |
|--------|------|-------|
| Analyse | "Analyse" | Idle (enabled) / Loading ("Analysing...") / Disabled (analysis in progress) |
| Run Fix | "Run Fix" | Appears only after Analyse completes; idle enabled / loading ("Running...") / disabled mid-operation |

### Card Heading
| Element | Copy |
|---------|------|
| Card title | "Fix EUR→GBP Transfers" |
| Card description | "Detected transfer pairs from the last 7 days are analysed below. Click Analyse to find matches, then Run Fix to apply corrections." |

### States & Messages
| State | Heading | Body | Next Step |
|-------|---------|------|-----------|
| **Initial** (before Analyse) | (card title above) | (card description above) | Click "Analyse" button |
| **Analyse Loading** | "Analysing transfers..." | (spinner or dots animation) | Wait for API response |
| **No pairs found** | "No unreconciled EUR→GBP transfers found" | "All recent transfers are already reconciled or don't match the pattern." | (Optional retry button, or dismiss) |
| **Pairs found** | (table appears below) | Table header: "Detected Transfer Pairs" | Click "Run Fix" to proceed |
| **Run Loading** | "Fixing transfers..." | (spinner or dots animation) | Wait for completion |
| **Run success** | "N transfers fixed" | Bullet list: each pair's EUR amount, GBP amount, and accounts affected | (Dismiss/close card or reset to initial) |
| **API Error** | "Failed to analyse transfers" | Error message from API (e.g. "YNAB API unreachable") + "Please check your YNAB PAT and try again." | Offer retry button |

**Tone:** Plain English, non-technical. Explain what happened and what to do next.

### Error Scenarios
- **Analyse fails:** Show error message + retry button. Inline red alert box (background: #fef2f2, border: 1px #fecaca, text: #dc2626)
- **Run fails mid-operation:** Show which transfers were fixed before error occurred + error message + retry button
- **Network timeout:** "Connection lost. Please check your connection and try again."

### Destructive Actions
**Run Fix button:** Is considered destructive (deletes/modifies YNAB transactions). No additional confirmation prompt needed (the Analyse step serves as the preview gate); however, the button should be visually distinct and the success message should confirm what was done.

## Component Inventory

### New Components for Phase 29

#### 1. FixEurGbpTransfersCard
**Location:** `src/app/(dashboard)/tools/FixEurGbpTransfersCard.tsx`
**Type:** Client component (useState for loading states, API calls)
**Props:** None (reads settings/session via API)
**Style:** Matches existing TestParseForm and SettingsForm pattern

**States:**
1. **Initial:** Card with title, description, Analyse button
2. **Analyse loading:** Analyse button disabled, loading indicator
3. **No pairs:** Message stating no pairs found, dismiss button
4. **Pairs found:** Table of pairs + Run Fix button + Analyse button disabled/hidden
5. **Run loading:** Run Fix button disabled, loading indicator
6. **Success:** Result summary with list of fixed pairs
7. **Error:** Error message + retry button

**Styling:** Use the consistent S object pattern from TestParseForm:
```
section: white card, 12px border-radius, 1.5rem padding, subtle shadow
sectionTitle: 1.25rem (20px), weight 700, dark gray
sectionDesc: 0.8125rem (13px), weight 400, medium gray, 1.5 line-height
btnPrimary: #2563eb, white text, 0.875rem (14px), weight 700, 6px border-radius
error: background #fef2f2, border 1px #fecaca, text #dc2626, padding 0.625rem 0.875rem
```

#### 2. Transfer Pairs Table
**Location:** Within FixEurGbpTransfersCard (not a separate component)
**Columns:**
- Date (YYYY-MM-DD)
- EUR Out (amount, 2 decimal places)
- Account (€Wise Euro)
- GBP In (amount, 2 decimal places)
- Account (UK Current or GBP Wise)
- Confidence (percentage, e.g. "95%", styled green for >80%, yellow for 50-80%, red for <50%)

**Table styling:**
- Header: bold (700), font-size 0.8125rem (13px), text-align left, uppercase label styling
- Rows: alternating background (none / light gray on every other row for readability)
- Row height: ~2rem per row
- Margins: 1rem top + bottom

#### 3. Result Panel
**Location:** Within FixEurGbpTransfersCard (not separate)
**Shows after Run succeeds:**
- Heading: "N transfers fixed" (e.g. "3 transfers fixed")
- List of fixed pairs:
  - "EUR 123.45 → GBP 105.00 (€Wise Euro to UK Current)"
  - "EUR 50.00 → GBP 42.50 (€Wise Euro to GBP Wise)"
  - etc.
- Result card styling: background #f0fdf4, border 1px #bbf7d0, padding 1rem, border-radius 8px, green text #166534

## User Flows

### Flow 1: Analyse → Pairs Found → Run → Success
1. User visits `/tools`
2. Sees "Fix EUR→GBP Transfers" card with Analyse button
3. Clicks "Analyse" → GET `/api/tools/fix-eur-transfers?dry=true`
4. API returns array of transfer pairs
5. Component renders table of pairs with Analyse button disabled and Run Fix button enabled
6. User reviews pairs in table
7. Clicks "Run Fix" → POST `/api/tools/fix-eur-transfers`
8. Component shows loading state
9. API returns success with list of fixed pairs
10. Component renders result panel with "N transfers fixed" + list
11. User can reset card (return to initial state) or navigate away

### Flow 2: Analyse → No Pairs Found
1. User clicks "Analyse"
2. API returns empty array
3. Component shows "No unreconciled EUR→GBP transfers found" message
4. Analyse button re-enabled or dismiss button shown

### Flow 3: Analyse → Error
1. User clicks "Analyse"
2. API fails (401, 500, network error, etc.)
3. Component shows error message: "Failed to analyse transfers" + error details
4. Analyse button remains enabled or Retry button shown

### Flow 4: Run → Partial Success with Error
1. User clicks "Run Fix"
2. API fixes first 2 transfers, then fails on 3rd
3. Component shows: "2 transfers fixed (1 failed)" + list of successful pairs + error message
4. Retry button offered to fix remaining pair

## Interaction Details

### Button Behavior
- **Analyse button:** Disabled while loading. Cursor: pointer (enabled) / not-allowed (disabled)
- **Run Fix button:** Only visible after Analyse succeeds with results. Disabled while loading. Cursor: pointer (enabled) / not-allowed (disabled)
- **All buttons:** Opacity 0.6 when disabled, feedback on hover (slightly darker background or shadow)

### Loading Indicators
**Option A (simpler):** Replace button text with "Analysing..." / "Running..." and disable button
**Option B (preferred for clarity):** Add inline loading text before button while preserving button text, or show spinner icon before button text

*Recommendation:* Use Option A for consistency with existing TestParseForm ("Parse Email" → "Parsing...")

### Table Scrolling
If table exceeds viewport width on mobile/tablet:
- Horizontal scroll enabled on table container
- Table stays within card padding

### Copy-to-Clipboard (Optional Enhancement, Phase 30+)
Reserve button space next to transfer amounts for future "copy pair" functionality. Not required for Phase 29.

## Accessibility Notes

- **Buttons:** Use native `<button>` elements with `disabled` attribute
- **Links:** None in this component
- **Keyboard navigation:** Tab order: Analyse button → Run Fix button → (if applicable) Dismiss/Retry buttons
- **Focus states:** Native browser focus ring (blue outline) on buttons
- **Color contrast:** All text must pass WCAG AA (text on white, error text on light red, etc. all meet 4.5:1+)
- **Aria labels:** Add `aria-label="Loading"` or similar to spinners if used
- **Screen readers:** Error messages and result summaries should be announced via live region if using Announce API, or simply via semantic HTML
