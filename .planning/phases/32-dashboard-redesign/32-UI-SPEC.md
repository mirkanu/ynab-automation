## Dashboard Layout (Phase 32 Contract)

### Current State
The dashboard at `/dashboard` (routes at `(dashboard)/dashboard/page.tsx`) currently displays:
- "This Week" stat card (clickable to logs with filters)
- "Success Rate" stat card (clickable to logs with filters)
- "Last Transaction" card
- "Forwarding Address" card (from DASH-02, Phase 28)

### New State (Phase 32 Deliverable)

**Two-panel dashboard layout** replacing existing stat cards with structured section panels:

#### Panel 1: Email Automation Overview
**Card:** White background, 12px border-radius, 1.5rem padding, 1px 0 3px shadow (#111827 15% opacity)

**Header:**
- Title: "Email Automation" (22px/700, color #111827)
- Subtitle: "Email processing summary" (13px/400, color #6b7280, margin-top 0.5rem)

**Content rows (each row: 1rem gap between items, left-align label + right-align value):**
1. **Last Email Processed**
   - Label: "Last email processed" (13px/400, color #6b7280, uppercase, letter-spacing 0.05em)
   - Value: ISO timestamp OR "Never" if no emails (13px/400, color #374151)
   - Example: "2026-05-30T14:32:15Z" or "May 30, 2:32 PM"
   - Fallback copy if no data: "No emails processed yet"
   - Content row margin-bottom: 1rem

2. **Success Rate (This Week)**
   - Label: "Success rate (this week)" (13px/400, color #6b7280, uppercase, letter-spacing 0.05em)
   - Value: "{percentage}% ({successes}/{total})" (13px/400, color varies by rate)
   - Color logic: ≥80% green (#166534), 50-79% amber (#92400e), <50% red (#991b1b)
   - Fallback copy if no data: "No emails this week"
   - Content row margin-bottom: 1rem

3. **Last YNAB Transaction Created**
   - Label: "Last YNAB transaction" (13px/400, color #6b7280, uppercase, letter-spacing 0.05em)
   - Value: "{payee} · {amount}" on first line, "Created {date/time}" on second line (both 13px/400, color #374151)
   - Fallback copy if no data: "No transactions created yet"
   - Example:
     ```
     Amazon
     £45.99 · May 30, 2:30 PM
     ```
   - Content row margin-bottom: 0 (last item)

#### Panel 2: Currency Tools Status
**Card:** White background, 12px border-radius, 1.5rem padding, 1px 0 3px shadow (#111827 15% opacity)

**Header:**
- Title: "Currency" (22px/700, color #111827)
- Subtitle: "Financial tools status" (13px/400, color #6b7280, margin-top 0.5rem)

**Content rows (each row: 1rem gap between items, left-align label + right-align value):**

1. **EUR→GBP Transfer Fix (Last Run)**
   - Label: "EUR→GBP Transfer fix" (13px/400, color #6b7280, uppercase, letter-spacing 0.05em)
   - Value: "{date/time}" (13px/400, color #374151) OR "Never run" if no run history
   - Sub-value: "Fixed {N} pairs" (13px/400, color #9ca3af, only shown if run completed successfully)
   - Example:
     ```

   - Content row margin-bottom: 1rem

2. **EUR Conversion (Last Run)**

   - Value: "{date/time}" (13px/400, color #374151) OR "Never run" if no run history
   - Sub-value: "Converted {N} transactions" (13px/400, color #9ca3af, only shown if run completed successfully)
   - Example:
     ```
     EUR Conversion
     May 29, 10:15 AM
     Converted 8 transactions

   - Content row margin-bottom: 1rem

3. **EUR Reconciliation (Last Run)**
   - Label: "EUR Reconciliation" (13px/400, color #6b7280, uppercase, letter-spacing 0.05em)

## Real-Time Updates (DASH-04 Requirement)

**Current behavior:** Dashboard requires manual page reload after running tools.

**Phase 32 requirement:** Currency panel updates after running corresponding tools without manual page reload.

**Implementation approach:**
- Email Automation panel: Uses server-side `getDashboardStats()` query — no real-time update needed (activity log updates naturally; this panel shows this-week aggregates)
- Currency panel: After `POST /api/tools/{tool}` completes, the dashboard component **must poll or refetch** the latest tool-run metadata to display updated "Last run: {date}" + outcome values

**Specific tools triggering updates:**
1. `POST /api/tools/fix-eur-transfers` → update EUR→GBP Transfer fix row
2. `POST /api/tools/eur-conversion` (future Phase 33) → update EUR Conversion row
3. `POST /api/tools/reconcile-eur` → update EUR Reconciliation row

**Implementation note:** Phase 32 scope is the UI contract only. The planner/executor will determine whether to:
- Add a `getLastToolRuns()` server function (simple query to ActivityLog/Setting with timestamps)
- Implement `setInterval()` polling on the currency panel (naive but works for household volume)
- Add WebSocket/Server-Sent Events (overkill for single admin)

UI contract guarantees: After tool completes, currency panel values are current within 5 seconds without manual reload.

## Data Dependencies

### Email Automation Panel Source
- `getDashboardStats()` from `src/lib/activity-log-queries.ts` returns:
  - `thisWeek.total` — count of emails processed this week
  - `thisWeek.successes` — count of successful emails this week
  - `thisWeek.rate` — percentage success rate
  - `lastTransaction.retailer` — payee name (merchant/retailer)
  - `lastTransaction.amount` — transaction amount (numeric)
  - `lastTransaction.date` — transaction date string (formatted for display)
  - `lastTransaction.receivedAt` — ISO timestamp when email was received

### Currency Panel Source
- Requires new query function `getLastToolRuns()` or similar (to be implemented by executor)
- Returns for each tool:
  - EUR→GBP Transfer fix: last run date, number of pairs fixed, success status
  - EUR Conversion: last run date, number of transactions converted, success status
  - EUR Reconciliation: last run date, reconciliation gap amount (£), success status

**Note:** Currency panel data does NOT exist in database schema yet. Phase 32 UI-SPEC assumes executor will:
1. Store tool-run metadata in ActivityLog or new ToolRun table
2. Create a query function to fetch latest runs
3. Implement the polling/update mechanism
